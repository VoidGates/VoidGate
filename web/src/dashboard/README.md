# Painel de monitoramento

`events.ts` define o formato de cada evento e gera eventos simulados: 30 minutos de histórico ao abrir e uma mensagem nova a cada 2 a 4 segundos, com ondas de ataque. `status.ts` calcula os totais e a situação de cada tipo de ameaça nos últimos 15 minutos (0 a 2 calmo, 3 a 9 atenção, 10 ou mais sob ataque). `status.ts` também agrupa as ameaças por minuto para o gráfico e separa as bloqueadas dos últimos 5 minutos, que se acumulam no portão do rio. Também monta a lista de ameaças recentes (as mensagens liberadas sem mudança ficam de fora) e classifica o risco: 0,75 ou mais é alto, 0,40 ou mais é médio. `useSimulatedEvents.ts` liga a simulação à tela e para tudo quando o painel está pausado.

`api.ts` lê `GET /v1/events` e traduz os motivos em categorias: `content.prompt_injection` e `content.invisible_unicode` viram prompt injection, `content.personal_data` vira informação indevida; com mais de um, vale o mais grave. Eventos malformados são pulados, e campos que não fazem parte do contrato nunca chegam à tela. `useEventFeed.ts` escolhe a fonte: no `npm run dev` com a API no ar, consulta os dados reais a cada 2 segundos usando o cursor para buscar apenas eventos novos e seguir páginas adicionais; sem a API, ou no site publicado, usa a simulação. Quando há lacuna ou reinício, o painel informa que os dados reais estão incompletos. No modo real, `MONITORED_BY_API` diz quais tipos a API detecta; fraude por arquivo fica marcada como não monitorada, e os motivos aparecem em português no lugar do trecho.

Os trechos simulados já vêm com dados pessoais escondidos. Os eventos reais não têm texto nenhum.
